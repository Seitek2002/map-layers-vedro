# Метеослои · Кыргызстан

Интерактивная карта с тремя GIS-слоями (температура, инсоляция, ветер), timeline и графиками.
React 19 · TypeScript (strict) · **Vedro** · **MapLibre GL JS** · **Recharts** · three.js.

**Демо:** https://seitek2002.github.io/map-layers-vedro/

```bash
npm install
npm run dev     # http://localhost:5173
npm test        # vitest: гонки запросов, модель времени, биндинг стора
npm run build   # tsc -b + vite build
```

Что попробовать: быстро протащить timeline (счётчик «отменено» растёт, карта не мигает);
кликнуть по графику (время меняется везде); кликнуть по карте (графики переключаются на ряд в точке);
включить «Инсоляцию» ночью (слой сообщает, что данных нет); «3D-метеостанция» — анемометр крутится
со скоростью ветра на выбранное время.

## 1. Архитектура

```
src/
  config/    реестр слоёв (единственное место, где описан слой), регион, ось timeline
  domain/    чистые модели: время, сетка, слой/кадр/ряд, цветовые шкалы — без React и карты
  data/      LayerDataApi (граница данных), mock-реализация, DataSync (загрузка/отмена)
  store/     Vedro-стор: состояние, селекторы, экшены, React-биндинг
  map/       MapView (React-оболочка), MapController (стор → MapLibre), рендереры, 3D
  panels/    UI: слои, timeline, аналитика (Recharts), диагностика запросов
```

Слой = **геометрия (статична, выводится из сетки)** + **значения по времени (кадры)**. У каждого слоя
своя пространственная сетка и своя временная ось: температура — ежечасно, ветер — раз в 3 часа,
инсоляция — только 05:00–20:00. Выбор времени резолвится в «valid time» слоя
(последний шаг ≤ выбранного: ветер на 04:00 показывает кадр 03:00, инсоляция в 22:00 — «нет данных»).

## 2. Почему MapLibre GL JS

- WebGL-рендеринг векторных данных — масштабируется на десятки слоёв лучше DOM/Canvas (Leaflet).
- **feature-state**: значения меняются без перетайлинга источника — ровно то, что нужно для timeline
  поверх статичной геометрии.
- Нативный 3D: `fill-extrusion` (здания) и custom layer для three.js (метеостанция).
- Open source, без токена и биллинга (Mapbox GL v2+ проприетарен и требует токен; Google Maps — ключ;
  OpenLayers хорош, но 3D только через Cesium). Подложка — OpenFreeMap, тоже без ключа.

## 3. Состояние в Vedro

```ts
AppState = {
  layers:   Record<LayerId, { enabled, opacity }>   // что выбрал пользователь
  timeline: { selected, playing }                   // единственное «выбранное время»
  probe:    { lngLat } | null                       // точка на карте для графиков
  frames:   Record<`${LayerId}@${time}`, Resource<LayerFrame>>   // кэш кадров
  series:   Record<`${LayerId}:${cell|'region'}`, Resource<LayerSeries>>
  network:  { inFlight, completed, aborted, failed }
}
```

- Стор создаёт `createVedro` (`Provider` → свой стор на каждый mount), все записи — через
  `store.dispatch`, только через `createActions(store)`; no-op изменения не диспатчатся.
- Загруженные данные лежат в **кэшах по ключу**, а не в слоте «текущие данные слоя» — на этом держится
  защита от гонок (п. 4).
- `useSelector` из vedro заменён на тонкий `useAppSelector` поверх `useSyncExternalStore`. Из исходников
  vedro: селектор захватывается один раз на mount (`useEffect(..., [])`) — селектор, зависящий от пропсов,
  продолжает читать старые пропсы (закреплено тестом в `useAppSelector.test.tsx`); обновления между
  render и подпиской теряются; равенство считается через `JSON.stringify` на каждый dispatch для каждого
  подписчика. Там же найдено: `dispatch(async cb)` не работает (`isAsyncFunction` проверяет
  `fn instanceof Promise`) — поэтому асинхронность целиком вне vedro, в сторе только синхронные записи.
  И повторный вызов unsubscribe в vedro удаляет чужого подписчика — обёрнут в идемпотентный `subscribe`.

## 4. Связь timeline → данные → карта и Recharts

```
Timeline / клик по графику ─► timeline.selected ─┐
Клик по карте ─────────────► probe ──────────────┤
Чекбоксы слоёв ────────────► layers ─────────────┤   (Vedro)
                                                 ▼
                        selectWantedRequests: активные слои × valid time (+ следующий шаг при play)
                                                 ▼
          DataSync: нет в кэше → запрос;  не нужно больше → abort;  ответ → frames/series[key]
                                                 ▼
               ┌─────────────────────────────────┼──────────────────────────────┐
               ▼                                 ▼                              ▼
     MapController → рендереры          LayerChart (Recharts)          Timeline (активный шаг
     кадр → плавный tween 450 мс        ReferenceLine/Dot на времени    на полосе каждого слоя)
```

Все три части читают одну цепочку селекторов (`selectResolvedTime`, `selectLayerFrame`, `selectSeriesKey`),
поэтому не могут разойтись. Синхронизация двусторонняя: клик по точке графика → `selectTime`,
клик по карте → `setProbe`. Графики связаны `syncId` c `syncMethod="value"` — hover синхронизируется
по времени, а не по индексу (у слоёв разная частота, индексы не совпадают).

**Гонки.** Ответ может записать только свой ключ: поздний ответ за 11:00 заполнит кэш 11:00 и никак не
заменит то, что показано для 12:00 — корректность не зависит от порядка ответов. Ненужные запросы
(протащили timeline дальше, выключили слой, сдвинули точку) отменяются через `AbortController`, а их
результат игнорируется, даже если транспорт всё-таки ответил. Пока новый кадр грузится, карта показывает
предыдущий приглушённым (без мигания), затем плавно перетекает. Проигрывание ждёт данных и префетчит
следующий шаг. Всё это проверено в `dataSync.test.ts` на транспорте, который нарочно игнорирует abort.

## 5. Границы ответственности

| Модуль | Отвечает за | Не знает о |
|---|---|---|
| `domain/` | модели и чистые функции | React, карте, сторе |
| `data/` | загрузку, кэш-политику, отмену | UI, карте |
| `store/` | состояние, производные данные, экшены | как это рисуется |
| `map/` | перевод состояния в MapLibre | React-рендерах (подписан на стор напрямую) |
| `panels/` | UI и Recharts | MapLibre, транспорте |

Камера (центр/зум/наклон) намеренно живёт в MapLibre, а не в сторе: при панорамировании это 60 dispatch/с.

## 6. Производительность

- Геометрия загружается в источник один раз; смена времени — только `setFeatureState` (без перетайлинга).
  Ветер: стрелка вращается layout-свойством, которое feature-state не умеет, поэтому ~60 точек
  переотправляются через `setData`; интерполируются компоненты u/v, а не углы (350°→10° — короткой дугой).
- MapController схлопывает изменения стора в одну синхронизацию на кадр анимации; рендереры
  игнорируют неизменившиеся вызовы. DataSync схлопывает всплеск dispatch в один проход на microtask
  и делает один dispatch на проход.
- Vedro уведомляет всех подписчиков на каждый dispatch — селекторы возвращают примитивы или стабильные
  ссылки, равенство `Object.is`/shallow; массивы данных — `Float32Array`.
- Recharts: данные графика пересчитываются только при смене ряда; шаг времени двигает лишь маркеры.
- three.js (≈130 КБ gzip) грузится динамическим импортом после карты; рендер-цикл 3D крутится, только
  пока модель в движении. Вендоры разнесены по чанкам, код приложения — 14 КБ gzip.
- Воркер MapLibre 6 ищется через `new URL(переменная, import.meta.url)` — Vite не может ни пре-бандлить
  это в dev, ни эмитнуть в prod; подключён явно через `?worker&url` + `setWorkerUrl`.

## 7. Масштабирование до 100+ слоёв

- Слой описывается одной записью в `config/layers.ts` (+ источник данных); `Record<LayerId, …>` заставляет
  компилятор указать на всё, что не заполнено. Новый слой существующего вида (grid/points/vectors)
  не трогает стор, карту и UI; новый вид визуализации — один рендерер и одна ветка в `createRenderer`.
- Стоимость синхронизации — O(активных слоёв), не O(всех): запросы, рендереры и графики только для включённых.
- Дальше бы добавил: LRU-вытеснение кэша кадров; группы/поиск/виртуализацию в списке слоёв; графики
  только для «закреплённых» слоёв (100 графиков бессмысленны); для плотных сеток — векторные/растровые
  тайлы с сервера по времени вместо GeoJSON; несколько vedro-сторов по доменам, если подписчиков станут тысячи.

## 8. Осознанные компромиссы

- Регулярные временные оси (start/step/count) и «valid time» без интерполяции данных между шагами —
  плавность только визуальная.
- Данные генерируются детерминированными формулами на клиенте, mock API: задержка 250–1200 мс и 6% ошибок
  (нарочно, чтобы были видны гонки и retry). Ряд в точке — по ближайшей ячейке, без интерполяции.
- Кэш без вытеснения (3 слоя × 24 шага — мелочь). Ошибка висит до явного «Повторить», без авто-ретраев.
- 3D-модель процедурная и на мелких зумах увеличена до читаемого размера — это ориентир, а не масштабная модель.
- Стили — простой CSS; линтер — oxlint (из шаблона Vite), без ESLint/Prettier/Husky.

**Что изменили или отклонили:**
- Первая версия (до подробного ТЗ) была на Leaflet с одним AbortController на слой. С появлением timeline и
  префетча это перестало работать: «слот на слой» выбрасывал бы префетч следующего шага. Переделали
  на ключевой кэш и MapLibre (feature-state, 3D).
- AI поначалу использовал штатный `useSelector` vedro; после чтения исходников заменили на биндинг
  через `useSyncExternalStore`.
- Проверка скриншотами поймала две ошибки AI: 3D-модель в реальном масштабе была невидима на обзорном
  зуме (сделали минимальный экранный размер), а слои данных ложились поверх 3D-зданий и заливали город
  (перенесли под здания и добавили затухание с зумом).
- Отклонил предложение перевести стили на styled-components (стек компании): тестовое оценивает
  инженерную часть, а миграция — лишний риск перед сдачей.
- Сократил README: первый вариант AI был вдвое длиннее, чем нужно.
